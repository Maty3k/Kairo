## Your test card

About 1 to 1.5 hours on the PC, once; longer if Windows needs a feature update.

1. **Update Windows.** Settings → Windows Update: install everything. Then look at Settings → System → About: on version 24H2 or older, take the 25H2 feature update (24H2 Home and Pro stopped getting updates on 2026-10-13); on 25H2 or 26H2, stay where you are. Under Advanced options → Active hours, set your evenings and nights. Claude will ask you to pause updates during soak-test weeks.
2. **Network and power.** Settings → Network & internet → your connection → **Private**. Settings → System → Power: sleep **Never** while Claude has PC work (until M9). On days you agree to tests while you're away, turn off Dynamic Lock and any screen-saver lock.
3. **Run the setup command.** Claude sends you the exact one-line command in chat, and [SETUP.md](../../SETUP.md) explains what it does. It holds nothing secret (a commit id and your Mac's public key), so messaging it to yourself is fine, but run only the command Claude sends you in this chat: a link of the same shape can point at someone else's copy of Kairo. On the PC, right-click **Start → Terminal (Admin)** and click **Yes**; the tab should say *Administrator: Windows PowerShell*. Paste the command, read what it will install, press **Y** and approve any prompts (20–40 minutes).
4. When it prints **DONE**, **send Claude the four lines it shows** (PC name, IP, user and host key), then **sign out and sign back in**.
5. **Smart App Control:** Start → type "Smart App Control" → tell Claude whether it is On, Evaluation or Off. If it isn't Off, Claude explains your two options (Q3) and recommends turning it off. M0 closes only when one of the two routes works.
6. **AMD Software: Adrenalin Edition → Record & Stream:** tell Claude whether Instant Replay is on, its length and its hotkeys. **Leave it on.**
7. **Tell Claude about your games:** the games and launchers you play, which ones use HDR, any you run as administrator, your keyboard layouts, your usual play times, and the days the PC may run tests while you're away.
8. **Hello test.** When Claude asks, a window called **Hello from Kairo** opens on your main monitor. Click it and press any key. Claude tells you which key arrived; say whether it's right.
9. **On the Mac:** free up space until at least 20 GB is free (about 12 GB today; see System Settings → General → Storage), then tell Claude. Claude then shows you Microsoft's licence for the Windows SDK files that cargo-xwin downloads; accept it only if you agree to it.
10. **Optional:** a Dev Drive for `C:\kairo`, or a Microsoft Defender exclusion for `C:\kairo\src\target` only, makes builds faster. Claude explains both, and skipping them is fine.

## M0 contract

Every M0 file uses these names exactly. They replace the sketch names in [cookbook §10.2–10.4](../research/15-implementation-cookbook.md#10-dev-loop-scripts) (`builds\`, `run\job.json`, `kairo-engine --ensure` every 5 minutes); the elevated twin of `\Kairo\Run` described there is not part of M0. To change a name, change it here first, then in every file that uses it.

**PC folders.** `C:\kairo` is the root.

| Path | Holds |
|---|---|
| `C:\kairo\src` | A non-bare clone with `receive.denyCurrentBranch=updateInstead`, branch `snapshot` checked out |
| `C:\kairo\bin\<build-id>\` | One build each; `C:\kairo\bin\current` is a directory junction to the active one; 3 builds kept |
| `C:\kairo\jobs\` | Job files; `\Kairo\Run` reads `next.json` |
| `C:\kairo\logs\` | Job results and output, `hello.log` |
| `C:\kairo\tools\` | FFmpeg, PresentMon, `gitconfig` (the Git settings of Claude's SSH sessions) |
| `C:\kairo\state\` | `watch.json` (rewritten every 1 s by the watch agent), `bootstrap-report.json` |

Permissions: Administrators and SYSTEM have full control of `C:\kairo` and own everything in it; you (and an OWNER RIGHTS entry, so a file's owner cannot rewrite its permissions) can read and run everything. Your own programs (`kairo-devrun`, `kairo-hello`, the watch agent, the doctor's PresentMon test) write only in `logs\` and `state\`, where you have Modify. So nothing running as you can change what the elevated SSH side runs or trusts. Records the elevated side trusts live in the admin-only folders (for example `tools/mac/pc`'s `bin\last-build.json`).

**Scheduled tasks** live in the folder `\Kairo\`. Principal: the interactive owner, LogonType Interactive, RunLevel Limited. Settings: Priority 4, ExecutionTimeLimit PT0S, MultipleInstances IgnoreNew.

| Task | Runs | When |
|---|---|---|
| `\Kairo\Run` | `C:\kairo\bin\current\kairo-devrun.exe run --job C:\kairo\jobs\next.json` | On demand |
| `\Kairo\Ensure` | `C:\kairo\bin\current\kairo-devrun.exe ensure` | At logon and every 1 minute; starts the watch agent if it isn't running, and exits fast |
| `\Kairo\Engine` | `C:\kairo\bin\current\kairo-devrun.exe engine` | On demand; in M0 it launches `kairo-hello.exe` |

**Files.**
- Job file (JSON): `{"id": string matching ^[A-Za-z0-9_-]{1,64}$, "cmd": [exe, args...], "cwd": string|null, "max_seconds": int, "abort_on_input": bool, "window": "visible"|"hidden"}`. A null `cwd` means `C:\kairo`, which jobs can read but not write: a job that writes files sets `cwd` to `C:\kairo\logs` or writes there by full path.
- Job result: `C:\kairo\logs\<id>.result.json` with `{"id","exit_code","aborted","reason","started_utc","ended_utc"}`; stdout and stderr in `C:\kairo\logs\<id>.out.log` and `<id>.err.log`.
- `watch.json`: `{"ts_utc","last_input_ms_ago","foreground_fullscreen","foreground_exe","busy"}`. Busy means input within the last 600 s or a fullscreen foreground window; the games list comes later. `foreground_exe` is the program's file name only while its window is fullscreen, otherwise null: which ordinary window is in front is not reported (house rules). The watch agent runs in your session because `GetLastInputInfo` only sees input in the session that calls it.

**Programs.**
- `kairo-hello.exe` opens a window titled "Hello from Kairo" on the primary monitor, with short instructions. It logs each key press with its QPC timestamp to `C:\kairo\logs\hello.log`; the house rules allow no hooks, so it only sees keys pressed while its own window has focus. It serves the named pipe `\\.\pipe\kairo-hello`: JSON-RPC 2.0, each message framed by a 4-byte big-endian length prefix, at most 1 MiB. Methods: `engine.hello` returns `{name, version, session_id, elevated}`; `hello.keys` returns recent key presses. Pipe DACL: SYSTEM and the current user only; remote clients are rejected.
- `kairo-cli.exe`: `kairo-cli ping [--pipe NAME]` and `kairo-cli keys`.

**Mac.** The SSH alias `kairo-pc` with the key `~/.ssh/kairo_pc`; the pc tool is `tools/mac/pc` (`tools/mac/pc <verb>`). The first connection pins the PC's host key with `tools/mac/ssh-setup.sh <ip> <user> <SHA256:fingerprint>`, using the *Host key* line of the bootstrap's DONE screen (`--trust-on-first-use` only when that line is missing). `tools/mac/pc` passes `StrictHostKeyChecking=yes` and `IdentitiesOnly=yes` itself, so no other `~/.ssh/config` entry can loosen either.

**SSH shell.** `DefaultShell` is `C:\Windows\System32\cmd.exe` with `DefaultShellCommandOption` `/d /c` (and `DefaultShellArguments` `/d` for interactive logins). This replaces cookbook §10.2's "DefaultShell = pwsh 7": a PowerShell DefaultShell loads your PowerShell profile, which any program running as you can change, into every elevated SSH session. sshd runs `"cmd.exe" /d /c "<command>"` as plain text (Win32-OpenSSH `w32-doexec.c`); `/d` skips the Command Processor AutoRun commands; and `tools/mac/pc` starts `"C:\Program Files\PowerShell\7\pwsh.exe" -NoProfile ... -EncodedCommand ...` itself. Its scripts then reset the session's environment to the machine's values (your user variables are inherited, and you can change them) and give Git the admin-only `C:\kairo\tools\gitconfig` (`GIT_CONFIG_GLOBAL`), so your `.gitconfig` is never read elevated.

**SSH server.** It fails closed: the Kairo firewall rule (only `sshd.exe`, TCP 22, the Private profile, only the physical adapters whose addresses are all private, only from their subnet) is in place before sshd first runs; that first run already has the key-only `sshd_config`; sshd starts with Windows only after `sshd -T` shows `passwordauthentication no`, `kbdinteractiveauthentication no` and `pubkeyauthentication yes`; and a failure stops sshd again and sets it to Manual.

**Builds.** `pc build` runs in the elevated SSH session, so every build script and proc-macro runs as an administrator. It therefore needs a committed `Cargo.lock` (it always passes `--locked`), refuses while `C:\.cargo` or `C:\kairo\.cargo` holds a config file (the bootstrap makes `C:\.cargo` admin-only), and builds into `C:\kairo\src\target`, the only place `pc deploy` copies from. Open item, which needs your approval because it changes this contract: move builds to your limited token, for example as a Limited S4U task like the doctor's PresentMon test.

**Bootstrap one-liner.** It is documented in SETUP.md and runs in an elevated Windows PowerShell 5.1. Claude fills in the commit SHA and the key in chat; they are never committed.

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/Maty3k/Kairo/<COMMIT-SHA>/tools/pc/bootstrap.ps1))) -MacKey '<public key>'
```

`raw.githubusercontent.com` also serves commits that exist only in a fork, so a commit pin alone does not prove the script is reviewed code from `main`. Claude hands out only a SHA for which `gh api repos/Maty3k/Kairo/compare/<SHA>...main --jq .status` prints `identical` or `ahead` (the commit is in `main`'s history) and whose CI run is green: the squash commit on `main`, never a pull-request branch's commit. The same rule holds for the `uninstall-dev.ps1` one-liner.

## Risks → fallbacks

- Tasks fail when created over SSH → the bootstrap creates them.
- Git over SSH misbehaves → bundle + scp.
- SSH is flaky → Claude Code on the PC.
- The SSH step fails → the bootstrap leaves sshd off (fail closed) and says so on the DONE screen; run the command again once Claude has fixed it.
- No adapter qualifies for the firewall rule (network not Private, or not a home-network address) → the rule stays off; fix the network and run the bootstrap again.
